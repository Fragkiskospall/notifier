= Πώς δουλεύει ο Notifier
:toc: left
:toc-title: Περιεχόμενα
:toclevels: 2
:icons: font
:source-highlighter: rouge

Ο Notifier ελέγχει σε τακτά διαστήματα το Open eClass, το RSS του τμήματος και
την πύλη φοιτητών. Συγκρίνει ό,τι βρήκε με όσα έχει ήδη δει και σε ειδοποιεί
μόνο για τα καινούργια. Δεν υπάρχει server: όλα τρέχουν στον υπολογιστή σου.

== Η μεγάλη εικόνα

....
 ┌──────────────────────────── ο υπολογιστής σου ────────────────────────────┐
 │                                                                           │
 │  ┌────────────┐   εγκαθιστά    ┌──────────────────────────────────────┐  │
 │  │  Launcher  │ ─────────────▶ │  Χρονοπρογραμματιστής λειτουργικού   │  │
 │  │ (PySide6)  │                │  macOS: launchd (LaunchAgents)       │  │
 │  └─────┬──────┘                │  Windows: Task Scheduler (κρυφά)     │  │
 │        │ αποθηκεύει            └──────────────────┬───────────────────┘  │
 │        ▼                                          │ ξυπνά το ίδιο         │
 │  ┌────────────────────┐                           │ εκτελέσιμο με όρισμα  │
 │  │ Keychain /         │ ◀──── κωδικοί ────┐       ▼                       │
 │  │ Credential Manager │                   │  ┌──────────────────────┐    │
 │  └────────────────────┘                   └──│  Job                 │    │
 │                                              │  check · grades      │    │
 │  ┌────────────────────┐   seen.db.enc        │  digest · labs       │    │
 │  │ state/ (AES-GCM)   │ ◀──────────────────▶ └──────────┬───────────┘    │
 │  └────────────────────┘                                 │                │
 └─────────────────────────────────────────────────────────┼────────────────┘
                                                           │ HTTPS
              ┌──────────────────────┬─────────────────────┼──────────────┐
              ▼                      ▼                     ▼              ▼
        Open eClass            RSS τμήματος          Πύλη φοιτητών     ntfy / SMTP
     (ανακοινώσεις,                                   (βαθμοί)        (ειδοποιήσεις)
      εργασίες, ομάδες)
....

Ένα εκτελέσιμο κάνει δύο δουλειές:

* χωρίς ορίσματα ανοίγει τον *launcher* (το παράθυρο ρυθμίσεων),
* με όρισμα (`check`, `grades`, `digest`, `labs`) τρέχει ένα *job* χωρίς
  παράθυρο και κλείνει.

Ο χρονοπρογραμματιστής του λειτουργικού καλεί το ίδιο εκτελέσιμο με το σωστό
όρισμα. Έτσι η εφαρμογή δεν μένει ανοιχτή στο παρασκήνιο.

== Τα jobs

[cols="1,2,3",options="header"]
|===
| Job | Πότε | Τι κάνει

| `check`
| κάθε 30 λεπτά
| Νέες ανακοινώσεις από τα μαθήματα του eClass και από το RSS του τμήματος.

| `grades`
| κάθε 30 λεπτά
| Νέοι ή αλλαγμένοι βαθμοί στην πύλη φοιτητών, όπου υποστηρίζεται.

| `digest`
| 08:00, 14:00, 21:00
| Σύνοψη εργασιών με προθεσμίες, ταξινομημένες από την πιο κοντινή.

| `labs`
| με την πρώτη σύνοψη της ημέρας
| Υπενθύμιση για εργαστήρια της ημέρας, από τις ομάδες χρηστών του eClass.
|===

Τα ωράρια ορίζονται στο `system/base.py` (`default_jobs`) και αλλάζουν από τον launcher.

== Ένας κύκλος ελέγχου, βήμα βήμα

Παράδειγμα με το `check`:

....
  launchd / Task Scheduler
          │
          ▼
  1. Φόρτωση ρυθμίσεων ─────── config.toml + κατάλογος πανεπιστημίων
          │                    (eclass_url, RSS τμήματος, πύλη)
          ▼
  2. Κωδικοί ─────────────── Keychain / Credential Manager → μεταβλητές περιβάλλοντος
          │
          ▼
  3. Άνοιγμα state ────────── seen.db.enc ──αποκρυπτογράφηση──▶ προσωρινό seen.db
          │
          ▼
  4. Συλλογή ─────────────── login στο eClass, λίστα μαθημάτων,
          │                  ανακοινώσεις κάθε μαθήματος (RSS ή HTML),
          │                  RSS τμήματος
          ▼
  5. Σύγκριση ────────────── SeenStore.diff(): κρατά μόνο ό,τι δεν έχει ξαναδεί
          │
          ├── τίποτα νέο ──▶ τέλος
          ▼
  6. Ειδοποίηση ──────────── desktop · ntfy · email (όσα είναι ενεργά)
          │
          ▼
  7. Αποθήκευση ──────────── commit στο SQLite → κρυπτογράφηση → seen.db.enc
                             το προσωρινό αρχείο σβήνεται
....

Αν αποτύχει η αποστολή ειδοποίησης, η βάση κάνει rollback. Τα στοιχεία δεν
σημειώνονται ως «ειδωμένα» και ξαναδοκιμάζονται στον επόμενο κύκλο.

== Πώς ξέρει τι είναι «νέο»

Κάθε στοιχείο έχει σταθερό αναγνωριστικό (`uid`):

[cols="1,2",options="header"]
|===
| Πηγή | uid

| Ανακοίνωση eClass | `eclass:<κωδικός μαθήματος>:<an_id>`
| RSS τμήματος | `dept:<guid ή link>`
| Βαθμός | μάθημα + εξεταστική, με αποθηκευμένη την προηγούμενη τιμή
|===

Τα `uid` που έχει δει γράφονται στο `seen.db` (SQLite).

Την *πρώτη φορά* που εμφανίζεται μια πηγή, π.χ. ένα νέο μάθημα, όλες οι
υπάρχουσες ανακοινώσεις της καταγράφονται *χωρίς* ειδοποίηση. Έτσι η πρώτη
εκτέλεση δεν σου στέλνει 200 παλιές ανακοινώσεις.

== Πανεπιστήμια: ο κατάλογος

Κάθε ίδρυμα είναι ένα αρχείο TOML στο `catalog/universities/`. Από εκεί η
εφαρμογή παίρνει:

* τη διεύθυνση του Open eClass,
* τα RSS των τμημάτων,
* αν υποστηρίζονται βαθμοί και πού βρίσκεται η πύλη φοιτητών.

Στο `config.toml` αρκεί να γράψεις:

[source,toml]
----
[university]
id = "uniwa"
department = "ice"
----

Για να προσθέσεις ίδρυμα, δες το link:PROSTHIKI-PANEPISTIMIOU.md[PROSTHIKI-PANEPISTIMIOU.md].

== Απόρρητο και αποθήκευση

....
  Κωδικοί πανεπιστημίου ──▶ Keychain (Mac) / Credential Manager (Windows)
  STATE_KEY (32 bytes)   ──▶ Keychain / Credential Manager
  Ιστορικό (seen.db)     ──▶ state/seen.db.enc   AES-256-GCM
  Τελευταίες εκτελέσεις  ──▶ logs/runs.json       μόνο ώρα και ok/αποτυχία
....

* Το SQLite σε απλή μορφή υπάρχει μόνο σε προσωρινό φάκελο (`0700`) όσο τρέχει
  ένα job.
* Το `.enc` ξαναγράφεται μόνο όταν άλλαξε το περιεχόμενο.
* Αν χαθεί το κλειδί, το ιστορικό ξαναχτίζεται από την αρχή, χωρίς ειδοποιήσεις.
* Μέσα στο κρυπτογραφημένο αρχείο υπάρχει μετρητής έκδοσης, και η τελευταία τιμή
  του κρατιέται στο Keychain / Credential Manager. Αν κάποιος βάλει στη θέση του
  ένα παλιότερο αντίγραφο, η εφαρμογή το απορρίπτει.
* Οι κωδικοί διαβάζονται από το Keychain / Credential Manager τη στιγμή που
  χρειάζονται και δεν μπαίνουν στις μεταβλητές περιβάλλοντος.
* Το ntfy δέχεται μόνο `https://` και το κανάλι έχει τυχαίο όνομα 128 bit.
* *Ιδιωτική λειτουργία* (`private = true`): το ntfy και το email λένε μόνο
  «3 νέες ανακοινώσεις», χωρίς τίτλους, μαθήματα ή βαθμούς. Οι λεπτομέρειες
  φαίνονται μόνο στις ειδοποιήσεις του υπολογιστή.
* Η «Διαγραφή όλων» στον launcher σβήνει jobs, κωδικούς, ρυθμίσεις και ιστορικό.

== Ειδοποιήσεις

[cols="1,3",options="header"]
|===
| Κανάλι | Λεπτομέρειες

| Desktop
| Ειδοποίηση του λειτουργικού, μία ανά στοιχείο, με link.

| ntfy
| Push στο κινητό μέσω ntfy.sh ή δικού σου ntfy server. Το topic το διαλέγεις
  εσύ και το βλέπει μόνο όποιος το ξέρει.

| Email
| Μέσω SMTP, με απλό κείμενο και HTML.
|===

== Ανά λειτουργικό

[cols="1,2,2",options="header"]
|===
| | macOS | Windows

| Jobs
| LaunchAgents `gr.fragkiskosource.notifier.*`
| Κρυφά tasks στο `\FragkiskOSource\`, με «εκτέλεση όταν γίνει διαθέσιμο»

| Κωδικοί
| Keychain
| Credential Manager

| Παρατήρηση
| Το app πρέπει να είναι στο /Applications, όχι σε Desktop, Documents ή Downloads.
| Τρέχει με `pythonw` ή το `.exe`, χωρίς παράθυρο κονσόλας.
|===

Ό,τι αλλάζει ανά λειτουργικό ζει στο `system/`. Το `system.current()` διαλέγει
το σωστό backend.

== Δομή κώδικα

....
src/uniwa_notifier/
├── cli.py            σημείο εισόδου: launcher ή job
├── config.py         config.toml + κατάλογος → Settings
├── catalog/          ένα TOML ανά πανεπιστήμιο
├── eclass/           login και parsing σελίδων Open eClass
├── services/         πύλη φοιτητών (βαθμοί)
├── feeds.py          RSS / Atom
├── jobs/             announcements · grades · digest · labs
├── notify/           desktop · ntfy · email
├── state.py          SeenStore: τι έχουμε δει
├── vault.py          κρυπτογράφηση του state
├── secrets.py        Keychain / Credential Manager
├── runs.py           πότε έτρεξε τελευταία κάθε job
├── system/           macOS · Windows · Linux backends
└── launcher/         οθόνες PySide6 και λογική εγκατάστασης
....

== Από τη γραμμή εντολών

[source,bash]
----
python -m uniwa_notifier check --dry-run -v   # δείχνει τι θα έστελνε, χωρίς αποστολή
python -m uniwa_notifier digest --dry-run
python -m uniwa_notifier grades
python -m uniwa_notifier labs
----

Με `--dry-run` δεν στέλνεται τίποτα και δεν αλλάζει το ιστορικό.

== Build και releases

* Το *CI* (`ci.yml`) τρέχει pytest και ruff σε Linux, Windows και macOS σε κάθε
  pull request.
* Το *release* (`release.yml`) χτίζει με PyInstaller το `.app` και το `.exe`
  όταν μπει tag `v*`, και τα ανεβάζει στο GitHub Release.
